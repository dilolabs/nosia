# Running Nosia with Flisk (optional)

**`docker compose` stays the main way to run Nosia** (README, *Quickstart*). This adds an optional
[Flisk](https://flisk.sh) setup: each container has a small `service.json` under [`services/nosia/`](../services/nosia),
and `.autogenerated/docker-compose.yml` is generated from those files. Nothing here changes `docker-compose.yml`,
`install.sh` or how Nosia is deployed.

## Start with Flisk

Needs Docker and Flisk 1.4.27 or later (`npm install -g @flisk-sh/flisk`; `flisk doctor` checks the rest). Like `docker-compose.yml`, the `models` need Docker Model Runner (Docker Desktop, or the `docker model` plugin). Use the same `.env` as for
`docker compose` (`./install.sh` writes one, or copy `.env.example` and fill in the secrets and `POSTGRES_*`/`DATABASE_URL`).

```sh
flisk up nosia
flisk status
flisk logs --service web
flisk down
```

## Or start the generated Compose file, without Flisk

`.autogenerated/docker-compose.yml` is plain Compose. Compose reads `.env` from the folder of the file it is given, so
pass the project's `.env` from the repository root:

```sh
docker compose --env-file .env -f .autogenerated/docker-compose.yml up -d
```

It uses the **same Docker volumes** as `docker-compose.yml` (`nosia_postgres-db-data`, `nosia_rails-storage`,
`nosia_caddy-data`, `nosia_caddy-config`), so an existing install keeps its data, with no copy step. Stop one before
starting the other: both publish 80, 443 and 127.0.0.1:5432.

| `docker-compose.yml` | `service.json` (generated Compose) |
|---|---|
| `command: bundle exec rails db:prepare` on `dilolabs/nosia` | `services/nosia/db-migrate/Dockerfile` (`FROM dilolabs/nosia:latest` + that `CMD`) |
| `command: bundle exec rake solid_queue:start` | `services/nosia/solidq/Dockerfile` |
| `"80:80"`, `"443:443"` (every interface) | `extraPorts` with `"bind": "0.0.0.0"` |
| `"127.0.0.1:5432:5432"` | `extraPorts` on 127.0.0.1 |
| `healthcheck`, `depends_on` conditions, `models` | `healthCheck`, `dependsOn`, `models` |
| `restart: on-failure:5` | `on-failure:5` |

## Keeping them in step

Edit a `service.json`, then regenerate and commit the Compose file:

```sh
npx @flisk-sh/flisk-export@0.9.0 compose . --force
```

CI runs the same command with `--check`, and also re-imports `docker-compose.yml` and fails if the `service.json` files or the generated file would change, so a Compose edit nobody re-imported is caught.
If `docker-compose.yml` changes, `flisk import .` re-reads it into the `service.json` files.
